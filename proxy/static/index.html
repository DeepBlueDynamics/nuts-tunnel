Capabilities

Path-based routing

No wildcard DNS or custom domains. Every tunnel is reachable under one domain at /<name>/.

WebSocket transport

Client holds a persistent WebSocket out. No open ports on your machine, no inbound firewall rules.

Auto-reconnect

Exponential backoff on disconnect. Tunnels survive network blips, laptop sleep, and Cloud Run cold starts.

Multi-service

One client process exposes many local ports. Run your whole dev stack through a single connection.

Self-hostable

One Dockerfile, one env var. Deploy your own proxy to any Cloud Run project and point clients at it.

NUTS auth

Clients authenticate with an ahp_ token from auth.nuts.services. Token gates which tunnel names the client can claim.

Quick start

# 1. Install the client
curl -fsSL https://tunnel.nuts.services/install.sh | sh

# 2. Get an ahp_ token from your dashboard
#    https://auth.nuts.services/dashboard

# 3. Expose localhost:3000 as "myapp"
nuts-client --token ahp_yourtoken --service myapp=3000

# Now reachable at:
https://tunnel.nuts.services/myapp/

# Expose multiple ports in one connection
nuts-client --token ahp_yourtoken \
  --service api=8000 \
  --service web=3000 \
  --service db-admin=5050
